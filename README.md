南山大学 理工学部 電子情報工学科 横山哲郎の担当する電子情報工学演習で使う，
可逆計算に関する日本語のセミナー資料である。

**これらは査読を受けた論文ではない。** ゼミで読むための解説として書いたものである。

有界な全数検査・機械実験・予想）は各資料の中で区別して書いてある。

### RC-01 鎖上の空間最適可逆ペブリングの増大率

可逆計算では中間結果を捨てられないので、消すには逆計算が要る。その代価を捉える
最小の模型が鎖上の可逆ペブルゲームである。空間がちょうど最小のときの時間の増大率
`c` が厳密に決まったという結果と、その証明の筋を解説する。`c = 2^(1+κ*)`
（数値では 2.5170648368938…）。この恒等式は Lean 4 で仮定を持たない形で証明されている。

### RC-02 消去を許した可逆ペブリング

不可逆な消去を有限回だけ許すと、可逆な計算はどれだけ速くなるか。
飽和定理（手数が絶対的な床 `2n-1` に達するのは消去回数が `⌈(n-1)/(p-1)⌉-1` 以上の
ときちょうどである）を、1 ページの数え上げで証明する。
消去とペブルが交換可能な資源でないこと、手数が鎖の長さについて単調でないことも示す。

### RC-03 可逆プログラムは何を払っているか

Janus 系のコーパス 111 本について、生存状態・スタック・時間を同時に実測した資源アトラス。
消去が使われないだけでなく中間結果も片づけられない。書き込みのあった配列の約 65% は
値を 0 に戻す操作を一度も持たない。結果はすべて機械実験であり、定理は主張しない。

### RC-04 可逆小石並べゲーム

Bennett の可逆模倣における時間と空間のトレードオフを、紙と鉛筆で遊べる
小石並べゲームとして扱う演習資料。学部 3 年生のセミナーを想定している。
可逆計算の予備知識は仮定せず、Landauer の原理から説き起こす。
ゲームの可逆性・手数の偶奇性・手数の下界 `2T-1` は証明を付けた。
石の数の限界 `T <= 2^(S'-1)` は文献から引き、小さい `T` については
幅優先探索による全数検査で確かめている。Bennett の再帰的な戦略は
部分手順 Climb から漸化式を導く形で組み立てた。問題 10 問に解答例が付く。

他の資料と違い、原稿は Overleaf のプロジェクト「可逆計算入門」
（`a_revlec_v2.tex` の `pebble/` サブ文書）で維持しており、この repo には
PDF だけを収める。したがって `src/` に RC-04 の `.tex` は無い。

版 1.0（2020 年 9 月 30 日・6 頁）は改訂前の旧版で、
`https://tetsuo.jp/lecture/rc/pebble.pdf` として公開していたものと同一である。
版 2.0 で動機・規則の前提条件・証明・図の読み方・再帰的戦略の導出・
探索プログラム・発展問題を加えた。
あわせて、`T=8` の最小手数の誤り（`S'=4,5,6` に対する 27, 23, 21）を
全数探索で見つけ、25, 21, 19 に訂正している。

## 版と真正性

PDF の内容ハッシュを [SHA256SUMS](SHA256SUMS) に記録している。

```sh
sha256sum -c SHA256SUMS
```

版を改めるときは新しいファイル（`rc01-v1.1.pdf` など）を追加し、旧版は残す。

### 時刻証明（OpenTimestamps）

git のコミット日時は書き換えられるので、それだけでは「いつ存在したか」の証拠にならない。
そこで `SHA256SUMS` に **OpenTimestamps** の時刻証明を付けている
（[SHA256SUMS.ots](SHA256SUMS.ots)）。これは Bitcoin ブロックチェーンに固定された
第三者検証可能な証明であり、誰にも申請せずに作れて、後から改竄できない。

```sh
ots verify SHA256SUMS.ots   # SHA256SUMS が同じディレクトリにあること
```

⚠ `ots verify` は Bitcoin ノード（`~/.bitcoin/`）を必要とする。手元に無い場合は
`ots info SHA256SUMS.ots` で `BitcoinBlockHeaderAttestation(<高さ>)` が入っているかを見て、
そのブロックの時刻をブロックエクスプローラで確かめればよい。

押印直後は `Pending confirmation in Bitcoin blockchain` と出る。
ブロックに取り込まれた後（数時間から 1 日程度）に一度だけ

```sh
ots upgrade SHA256SUMS.ots  # 確定した証明を .ots に埋め込む
```

を実行し、更新された `.ots` をコミットすること。**この upgrade を忘れると、
カレンダーサーバが消えたときに証明が失われる。**

#### 資料を追加して SHA256SUMS を作り直すとき

`SHA256SUMS` が変わると、それまでの `.ots` はもう `SHA256SUMS` を検証できなくなる。
古い証明は「その時点で確かに存在した」という別個の証拠なので、捨てずに残す。手順は次のとおり。

1. `ots upgrade SHA256SUMS.ots` で**先に古い証明を確定させる**（pending のまま捨てない）
2. その時点の `SHA256SUMS` と `.ots` を日付つきの名前で残す
   （例: `SHA256SUMS-20260830` と `SHA256SUMS-20260830.ots`）
3. `make sums` で新しい `SHA256SUMS` を作る
4. `make stamp` で押印する（`ots stamp` は既存の `.ots` を上書きしないので、2 を先に済ませておくこと）
5. 数時間後に `make upgrade` して、更新された `.ots` をコミットする

| 証明 | 対象 | 状態 |
|---|---|---|
| [SHA256SUMS-20260830.ots](SHA256SUMS-20260830.ots) | [SHA256SUMS-20260830](SHA256SUMS-20260830)（RC-01〜RC-03） | Bitcoin ブロック 964698 等で確定済み |
| [SHA256SUMS.ots](SHA256SUMS.ots) | [SHA256SUMS](SHA256SUMS)（RC-01〜RC-04） | 2026-08-31 押印。**upgrade 待ち** |

## ビルド

和文クラス（jsarticle）なので **platex → dvipdfmx** を使う。pdflatex では通らない。

```sh
make        # src/ にある 3 本（RC-01〜RC-03）を組む
make sums   # SHA256SUMS を作り直す
```

RC-04 は原稿が別のプロジェクトにあるので `make` の対象外である。
組んだ PDF を `pdf/rc04-vN.M.pdf` として置き、`make sums` を実行する。
